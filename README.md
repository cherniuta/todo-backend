# todo-backend

Бекенд для приложения Effective Planning. Сервер хранит данные в JSON-файлах и отдает API для разгрузки inbox, проектов, задач, отложенных задач, текущей волны и режима экрана.

Базовый адрес API:

```text
http://localhost:3000/api
```

## Запуск

```powershell
cd M:\crsr\pr1\todo-backend\backend
go run .
```

Проверка тестов:

```powershell
cd M:\crsr\pr1\todo-backend\backend
go test ./...
```

## Файлы данных

Все данные лежат в папке `backend/data`:

| Файл | Что хранит |
| --- | --- |
| `inbox.json` | дела из inbox, которые еще не разобраны |
| `tasks.json` | обычные задачи/problems и отложенные задачи |
| `projects.json` | проекты и задачи внутри проектов |
| `current_wave.json` | задачи, выбранные в текущую волну |
| `mode.json` | текущий режим интерфейса, например `inbox` или `projects` |

## Общие форматы

### Задача

```json
{
  "id": 1,
  "text": "Описание задачи",
  "description": "Описание задачи",
  "source": "project",
  "projectId": 2,
  "projectName": "Название проекта",
  "status": "active",
  "delayUntil": "2026-05-13T19:00:00Z",
  "done": false,
  "createdAt": "2026-05-13T10:00:00Z",
  "updatedAt": "2026-05-13T10:00:00Z"
}
```

Возможные `status`:

| Статус | Значение |
| --- | --- |
| `inbox` | дело лежит в inbox |
| `active` | задача активна |
| `delayed` | задача отложена до даты `delayUntil` |
| `done` | задача выполнена |

### Проект

```json
{
  "id": 1,
  "name": "Демо",
  "description": "Подготовить демо",
  "sourceText": "Исходное дело из inbox",
  "tasks": [
    {
      "id": 123,
      "description": "Сделать слайды",
      "status": "active",
      "createdAt": "2026-05-13T10:00:00Z"
    }
  ],
  "createdAt": "2026-05-13T10:00:00Z",
  "updatedAt": "2026-05-13T10:10:00Z"
}
```

## Inbox

Inbox - это пул сырых дел. Пользователь добавляет туда все подряд, а потом в режиме разгрузки превращает каждое дело в проект, задачу или отложенную задачу.

Ручки `/api/inbox` и `/api/tasks` работают одинаково. `/api/tasks` оставлен для совместимости с текущим фронтом.

### `POST /api/tasks`

Добавляет новое дело в inbox.

Зачем нужно: кнопка "Добавить дело в Inbox".

Тело запроса:

```json
{
  "text": "Позвонить клиенту"
}
```

Ответ:

```json
{
  "id": 1,
  "text": "Позвонить клиенту",
  "status": "inbox",
  "createdAt": "2026-05-13T10:00:00Z"
}
```

### `GET /api/tasks?status=inbox`

Возвращает все дела из inbox.

Зачем нужно: фронт берет список дел для разгрузки.

Ответ:

```json
{
  "taskObjects": [
    {
      "id": 1,
      "text": "Позвонить клиенту",
      "status": "inbox",
      "createdAt": "2026-05-13T10:00:00Z"
    }
  ]
}
```

### `GET /api/tasks/next`

Возвращает одно следующее дело из inbox.

Зачем нужно: сценарий, где inbox разгружается по одному делу, а не всем списком сразу.

Ответ, если дело есть:

```json
{
  "task": {
    "id": 1,
    "text": "Позвонить клиенту",
    "status": "inbox",
    "createdAt": "2026-05-13T10:00:00Z"
  }
}
```

Ответ, если inbox пуст:

```json
{
  "task": null
}
```

### `DELETE /api/tasks/{id}`

Удаляет дело из inbox.

Зачем нужно: когда текущее дело закрыли/разобрали, оно должно исчезнуть из inbox.

Ответ, если удаление произошло:

```json
{
  "deleted": true,
  "task": {
    "id": 1,
    "text": "Позвонить клиенту",
    "status": "inbox"
  }
}
```

Ответ, если дело уже было удалено раньше:

```json
{
  "deleted": false
}
```

### `DELETE /api/tasks`

Очищает весь inbox.

Зачем нужно: после полной разгрузки можно удалить все оставшиеся дела из inbox одним действием.

Ответ:

```json
{
  "deleted": 5
}
```

### `PUT /api/tasks/{id}/delay`

Старая совместимая ручка для откладывания дела прямо из inbox. Удаляет дело из inbox и добавляет его в `tasks.json` со статусом `delayed`, если дата в будущем.

Зачем нужно: поддержка старого варианта фронта, где отложенная задача создавалась через id inbox-дела.

Тело запроса:

```json
{
  "delayUntil": "2026-05-13T19:00:00Z"
}
```

Ответ:

```json
{
  "id": 1,
  "text": "Позвонить клиенту",
  "description": "Позвонить клиенту",
  "status": "delayed",
  "delayUntil": "2026-05-13T19:00:00Z",
  "createdAt": "2026-05-13T10:00:00Z"
}
```

## Problems

Problems - это отдельные задачи, которые появились во время разгрузки inbox и не были привязаны к проекту. Они хранятся в `tasks.json`.

### `POST /api/problems`

Добавляет задачу/problem.

Зачем нужно: кнопка "Задача" при разгрузке inbox.

Тело запроса, которое сейчас отправляет фронт:

```json
{
  "description": "Написать письмо клиенту"
}
```

Также поддерживается формат:

```json
{
  "text": "Написать письмо клиенту",
  "description": "Подробности задачи",
  "sourceText": "Исходное дело из inbox"
}
```

Ответ:

```json
{
  "id": 1,
  "text": "Написать письмо клиенту",
  "description": "Написать письмо клиенту",
  "status": "active",
  "createdAt": "2026-05-13T10:00:00Z"
}
```

### `GET /api/problems`

Возвращает все задачи/problems.

Зачем нужно: получить все задачи, которые отсортировали во время разгрузки inbox.

Ответ:

```json
{
  "problems": [
    {
      "id": 1,
      "text": "Написать письмо клиенту",
      "description": "Написать письмо клиенту",
      "status": "active",
      "createdAt": "2026-05-13T10:00:00Z"
    }
  ],
  "tasks": [
    {
      "id": 1,
      "text": "Написать письмо клиенту",
      "description": "Написать письмо клиенту",
      "status": "active",
      "createdAt": "2026-05-13T10:00:00Z"
    }
  ],
  "taskObjects": [
    {
      "id": 1,
      "text": "Написать письмо клиенту",
      "description": "Написать письмо клиенту",
      "status": "active",
      "createdAt": "2026-05-13T10:00:00Z"
    }
  ]
}
```

`problems` - основное поле для текущего фронта. `tasks` и `taskObjects` оставлены для совместимости.

### `GET /api/problems?status=active`

Возвращает только задачи с указанным статусом.

Зачем нужно: фильтрация активных/отложенных задач.

Примеры:

```text
GET /api/problems?status=active
GET /api/problems?status=delayed
GET /api/problems?status=all
```

При чтении problems бек автоматически переводит просроченные `delayed` задачи в `active`, если `delayUntil` уже наступил.

### `DELETE /api/problems/{id}`

Удаляет задачу/problem.

Зачем нужно: когда problem выбрали в текущую волну или решили убрать из пула.

Ответ:

```json
{
  "deleted": true,
  "problem": {
    "id": 1,
    "description": "Написать письмо клиенту",
    "status": "active"
  }
}
```

Если задача уже удалена:

```json
{
  "deleted": false
}
```

## Delayed

### `POST /api/delayed`

Добавляет отложенную задачу.

Зачем нужно: кнопка "Отложенная задача" при разгрузке inbox.

Тело запроса, которое сейчас отправляет фронт:

```json
{
  "description": "Вернуться к этому вопросу",
  "delayUntil": "2026-05-13T19:00:00Z"
}
```

Ответ:

```json
{
  "id": 2,
  "text": "Вернуться к этому вопросу",
  "description": "Вернуться к этому вопросу",
  "status": "delayed",
  "delayUntil": "2026-05-13T19:00:00Z",
  "createdAt": "2026-05-13T10:00:00Z"
}
```

Если `delayUntil` уже наступил, задача сразу получит статус `active`.

## Projects

Projects - это пул проектов. Проект может иметь собственные задачи внутри поля `tasks`.

### `POST /api/projects`

Добавляет проект.

Зачем нужно: кнопка "Проект" при разгрузке inbox.

Тело запроса:

```json
{
  "name": "Запустить демо",
  "description": "Подготовить минимальный сценарий для показа"
}
```

Ответ:

```json
{
  "id": 1,
  "name": "Запустить демо",
  "description": "Подготовить минимальный сценарий для показа",
  "tasks": [],
  "createdAt": "2026-05-13T10:00:00Z"
}
```

### `GET /api/projects`

Возвращает все проекты.

Зачем нужно: экран проектов и выбор задач из проектов для текущей волны.

Ответ:

```json
{
  "projects": [
    {
      "id": 1,
      "name": "Запустить демо",
      "description": "Подготовить минимальный сценарий для показа",
      "tasks": [
        {
          "id": 123,
          "text": "Собрать список сценариев",
          "description": "Собрать список сценариев",
          "status": "active",
          "createdAt": "2026-05-13T10:00:00Z"
        }
      ],
      "createdAt": "2026-05-13T10:00:00Z"
    }
  ]
}
```

### `PUT /api/projects/{id}`

Обновляет проект целиком.

Зачем нужно: модальное окно проекта меняет название, описание и список задач проекта.

Тело запроса:

```json
{
  "id": 1,
  "name": "Запустить демо v2",
  "description": "Обновленное описание",
  "tasks": [
    {
      "id": 123,
      "description": "Собрать список сценариев",
      "createdAt": "2026-05-13T10:00:00Z"
    },
    {
      "id": 124,
      "description": "Проверить фронт",
      "createdAt": "2026-05-13T10:05:00Z"
    }
  ]
}
```

Ответ:

```json
{
  "id": 1,
  "name": "Запустить демо v2",
  "description": "Обновленное описание",
  "tasks": [
    {
      "id": 123,
      "text": "Собрать список сценариев",
      "description": "Собрать список сценариев",
      "status": "active",
      "createdAt": "2026-05-13T10:00:00Z"
    }
  ],
  "createdAt": "2026-05-13T10:00:00Z",
  "updatedAt": "2026-05-13T10:10:00Z"
}
```

### `DELETE /api/projects/{id}`

Удаляет проект из пула проектов.

Зачем нужно: убрать проект полностью.

Ответ:

```json
{
  "deleted": true,
  "project": {
    "id": 1,
    "name": "Запустить демо",
    "tasks": []
  }
}
```

Если проект уже удален:

```json
{
  "deleted": false
}
```

### `POST /api/projects/{projectId}/tasks`

Добавляет задачу внутрь проекта.

Зачем нужно: отдельная ручка для добавления задачи в проект, если фронт будет добавлять не через полное обновление проекта.

Тело запроса:

```json
{
  "description": "Проверить сценарий демо"
}
```

Ответ:

```json
{
  "project": {
    "id": 1,
    "name": "Запустить демо",
    "tasks": [
      {
        "id": 125,
        "text": "Проверить сценарий демо",
        "description": "Проверить сценарий демо",
        "status": "active"
      }
    ]
  },
  "task": {
    "id": 125,
    "text": "Проверить сценарий демо",
    "description": "Проверить сценарий демо",
    "status": "active"
  }
}
```

### `DELETE /api/projects/{projectId}/tasks/{taskId}`

Удаляет задачу из проекта.

Зачем нужно: когда задача проекта выбрана в текущую волну, ее надо стереть из проекта.

Ответ:

```json
{
  "deleted": true,
  "task": {
    "id": 123,
    "description": "Собрать список сценариев",
    "status": "active"
  }
}
```

Если задачи уже нет:

```json
{
  "deleted": false
}
```

## Current Wave

Current wave - текущая волна задач, которую пользователь выбрал для выполнения сейчас.

### `POST /api/current-wave`

Добавляет задачу в текущую волну.

Зачем нужно: при выборе задачи из проекта или из problems задача попадает в текущую волну.

Тело запроса для задачи из проекта:

```json
{
  "description": "Собрать список сценариев",
  "source": "project",
  "projectId": 1,
  "projectName": "Запустить демо"
}
```

Тело запроса для отдельной problem:

```json
{
  "description": "Написать письмо клиенту",
  "source": "problem"
}
```

Ответ:

```json
{
  "id": 1,
  "text": "Собрать список сценариев",
  "description": "Собрать список сценариев",
  "source": "project",
  "projectId": 1,
  "projectName": "Запустить демо",
  "status": "active",
  "createdAt": "2026-05-13T10:00:00Z"
}
```

### `GET /api/current-wave`

Возвращает все задачи текущей волны.

Зачем нужно: экран текущей волны должен получить все выбранные на выполнение задачи.

Ответ:

```json
{
  "tasks": [
    {
      "id": 1,
      "description": "Собрать список сценариев",
      "source": "project",
      "projectId": 1,
      "projectName": "Запустить демо",
      "status": "active"
    }
  ],
  "wave": [
    {
      "id": 1,
      "description": "Собрать список сценариев",
      "source": "project",
      "projectId": 1,
      "projectName": "Запустить демо",
      "status": "active"
    }
  ]
}
```

`tasks` - основное поле. `wave` продублировано на случай другого названия на фронте.

### `DELETE /api/current-wave/{id}`

Удаляет задачу из текущей волны.

Зачем нужно: пользователь может убрать задачу из текущего набора.

Ответ:

```json
{
  "deleted": true,
  "task": {
    "id": 1,
    "description": "Собрать список сценариев"
  }
}
```

### `PUT /api/current-wave/{id}`

Отмечает задачу текущей волны сделанной.

Зачем нужно: если фронт отправляет, что задача сделана, бек удаляет ее из `current_wave.json`.

Тело запроса:

```json
{
  "done": true
}
```

Также поддерживается:

```json
{
  "status": "done"
}
```

Ответ:

```json
{
  "deleted": true,
  "done": true,
  "task": {
    "id": 1,
    "description": "Собрать список сценариев",
    "status": "done",
    "done": true
  }
}
```

### `PATCH /api/current-wave/{id}`

Работает так же, как `PUT /api/current-wave/{id}`.

Зачем нужно: если фронт решит использовать PATCH для частичного обновления статуса.

## Mode

Mode - состояние текущего экрана приложения. Сейчас фронт использует его, чтобы понять, показывать inbox или проекты.

### `GET /api/mode`

Возвращает текущий режим.

Зачем нужно: при загрузке приложения фронт узнает, какой экран открыть.

Ответ:

```json
{
  "mode": "inbox"
}
```

### `PUT /api/mode`

Обновляет текущий режим.

Зачем нужно: после разгрузки inbox фронт переключает режим на `projects`.

Тело запроса, которое сейчас отправляет фронт:

```json
"projects"
```

Также поддерживается объект:

```json
{
  "mode": "projects"
}
```

Ответ:

```json
{
  "mode": "projects"
}
```

## CORS и OPTIONS

Все API-ручки выставляют заголовки:

```text
Access-Control-Allow-Origin: *
Access-Control-Allow-Methods: GET, POST, PUT, DELETE, OPTIONS
Access-Control-Allow-Headers: Content-Type
```

`OPTIONS` возвращает `200 OK`. Это нужно, чтобы фронт на Vite мог обращаться к Go-серверу на другом порту.

## Типичный сценарий работы фронта

1. Пользователь добавляет дело в inbox: `POST /api/tasks`.
2. Фронт получает inbox: `GET /api/tasks?status=inbox`.
3. При разгрузке пользователь создает проект: `POST /api/projects`.
4. Или создает отдельную задачу: `POST /api/problems`.
5. Или создает отложенную задачу: `POST /api/delayed`.
6. После закрытия текущего дела фронт удаляет его из inbox: `DELETE /api/tasks/{id}`.
7. После разгрузки фронт переключает экран: `PUT /api/mode` со значением `"projects"`.
8. Экран проектов получает проекты: `GET /api/projects`.
9. Пользователь редактирует проект и задачи внутри него: `PUT /api/projects/{id}`.
10. При выборе задачи на текущую волну фронт вызывает `POST /api/current-wave`.
11. Если задача пришла из проекта, фронт удаляет ее из проекта: `DELETE /api/projects/{projectId}/tasks/{taskId}`.
12. Если задача пришла из problems, фронт удаляет ее из problems: `DELETE /api/problems/{id}`.
13. Когда задача текущей волны выполнена, фронт отправляет `PUT /api/current-wave/{id}` с `{"done": true}`, и бек стирает ее из текущей волны.
